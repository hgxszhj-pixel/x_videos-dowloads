# 方案 C: 纯 Playwright 浏览器方案

> **目标:** 每次请求都通过 Playwright 浏览器完成，完全模拟真实用户行为

## 架构

```
┌─────────────────────────────────────────────────────────────┐
│                     MyLearningResolver                       │
├─────────────────────────────────────────────────────────────┤
│  ┌──────────────────────────────────────────────────────┐   │
│  │                  Playwright Browser                   │   │
│  │  1. 打开浏览器 (headless)                            │   │
│  │  2. 访问 SSO 登录页                                  │   │
│  │  3. 填写用户名/密码                                  │   │
│  │  4. 处理验证码（滑块/点选/短信）                      │   │
│  │  5. 登录成功后访问目标页面                           │   │
│  │  6. 提取视频信息                                     │   │
│  │  7. 关闭浏览器                                       │   │
│  └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

## 技术要点

1. **浏览器复用**: 使用 Browser Pool 避免频繁启动/关闭
2. **反检测**: 设置 `--disable-blink-features=AutomationControlled`
3. **验证码处理**: 需要对接打码平台或 AI 识别
4. **速度优化**: 并发限制，避免被检测

## 核心文件

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/resolvers/mylearning.rs` | 新建 | Playwright 驱动的解析器 |
| `src/resolvers/browser_auth.rs` | 新建 | 浏览器登录认证模块 |
| `src/cloakbrowser_client.rs` | 修改 | 扩展登录相关方法 |
| `src/resolvers/mod.rs` | 修改 | 导出新模块 |

## 优点 vs 缺点

| 优点 | 缺点 |
|------|------|
| ✅ 真实浏览器，难以被检测 | ❌ 速度最慢（3-8秒/请求） |
| ✅ 可处理复杂验证码 | ❌ 资源消耗高（200-500MB/浏览器） |
| ✅ 完全模拟用户行为 | ❌ 实现复杂度高 |
| ✅ 稳定获取登录态 | ❌ 不适合高频抓取 |

## 预估代码量

~900 行 Rust 代码（不含验证码识别）

## 备注

此方案速度最慢，资源消耗最大，**仅作为最后手段**。建议优先测试方案 A 或方案 B。
