# 方案 B: 混合方案（Cookie 池 + Playwright Fallback）

> **目标:** Cookie 池优先处理 80% 请求，当池耗尽或失败时使用 Playwright 自动化获取新 Cookie

## 架构

```
┌─────────────────────────────────────────────────────────────┐
│                     MyLearningResolver                       │
├─────────────────────────────────────────────────────────────┤
│  ┌──────────────────────────────────────────────────────┐   │
│  │                   CookiePool (优先)                   │   │
│  │  轮换策略: LRU + 命中率 + TTL + 健康检查              │   │
│  │  成功率: ~80%                                        │   │
│  └──────────────────────────────────────────────────────┘   │
│                           │ 失败                            │
│                           ▼                                 │
│  ┌──────────────────────────────────────────────────────┐   │
│  │           Playwright 自动化 (Fallback)                │   │
│  │  - 模拟浏览器登录                                     │   │
│  │  - 自动处理简单验证码（如滑动）                        │   │
│  │  - 获取新 Cookie 加入池                               │   │
│  │  成功率: ~95%                                        │   │
│  └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

## 切换逻辑

```
1. 从 Cookie 池获取 Cookie
2. 发起请求
3. 如果成功 → 返回结果
4. 如果失败（403/401/验证码页面）:
   a. 标记当前 Cookie 无效
   b. 尝试下一个 Cookie
   c. 如果池耗尽 → 调用 Playwright 自动化登录
   d. Playwright 成功 → 将新 Cookie 加入池 → 重试请求
   e. Playwright 失败 → 返回错误
```

## 优点 vs 缺点

| 优点 | 缺点 |
|------|------|
| ✅ 自动恢复，稳定性最高 | ❌ 实现复杂度高 |
| ✅ Cookie 池覆盖大部分场景 | ❌ Playwright 消耗资源 |
| ✅ 可处理简单的验证码 | ❌ 速度比纯 Cookie 池慢 |
| ✅ 自适应扩展 | ❌ 需要维护浏览器环境 |

## 适用场景

- 抓取量大，需要长期稳定运行
- 企业 SSO 有强制刷新机制
- 能接受偶尔的 Playwright 延迟
