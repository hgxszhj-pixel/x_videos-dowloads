# 方案 A: 纯 Cookie 池方案

> **目标:** 通过管理多个账号的 Cookie 池，实现企业 SSO 网站的稳定抓取

## 架构

```
┌─────────────────────────────────────────────────────────────┐
│                     MyLearningResolver                       │
├─────────────────────────────────────────────────────────────┤
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐      │
│  │  Account 1  │    │  Account 2  │    │  Account N  │      │
│  │  Cookie     │    │  Cookie     │    │  Cookie     │      │
│  │  (valid)    │    │  (valid)    │    │  (expired)  │      │
│  └─────────────┘    └─────────────┘    └─────────────┘      │
│                        CookiePool                            │
├─────────────────────────────────────────────────────────────┤
│  轮换策略: LRU + 命中率统计 + TTL 过期                        │
└─────────────────────────────────────────────────────────────┘
```

## 核心文件

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/resolvers/cookie_pool.rs` | 新建 | Cookie 池核心实现 |
| `src/resolvers/mylearning.rs` | 新建 | mylearning.cn 解析器 |
| `src/cloakbrowser_client.rs` | 修改 | 添加 `get_cookies()` 方法 |
| `src/resolvers/mod.rs` | 修改 | 导出新模块 |
| `src/config.rs` | 修改 | 添加 Cookie 池配置 |

## 优点 vs 缺点

| 优点 | 缺点 |
|------|------|
| ✅ 零成本 | ❌ 需要手动维护多个账号 |
| ✅ 速度快（纯 HTTP） | ❌ Cookie 有存活期限 |
| ✅ 资源消耗低 | ❌ 企业 SSO 可能有多因素认证 |
| ✅ 实现相对简单 | ❌ 同一 IP 频繁切换账号可能触发风控 |

## 适用场景

- 企业内网平台，账号资源充足
- 抓取频率不高（每天几百次）
- 能接受手动刷新 Cookie
