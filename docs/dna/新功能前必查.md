# 消灭派 · 新功能前必查 (Build-vs-Buy 30s Checklist)

> **起源**: 2026-09-13 采纳「五派」中的 **消灭派**。
> **目的**: AI 写新脚本/新模块前,**30 秒内确认没现成可复用**,避免"两年前就躺着一模一样的模块"血泪重演。
> **核心问题**: AI 默认行为是"造",不是"查";没显式 checklist 就会重复造轮子。

---

## 30 秒必查 3 项

> **任何**新功能 / 新脚本 / 新模块 / 新 skill,在写第一行业务代码之前,**必须**跑完这 3 项 grep:

### ① 查 skill (全局可复用工具)

```bash
# 关键词从用户需求里抽 2-3 个,小写 grep
ls ~/.claude/skills/ | grep -iE "<keyword1>|<keyword2>"
grep -rln "<keyword>" ~/.claude/skills/*/SKILL.md 2>/dev/null
```

**判定**:
- ✅ 有现成 skill → **直接用 / 复用**,不写新代码
- ❌ 没有 → 继续查②

### ② 查项目内模块

```bash
# 在项目根目录执行
grep -rn "<keyword>" src/ --include="*.rs" | head -10
grep -rln "<keyword>" scripts/
```

**判定**:
- ✅ 有类似模块 → 读它,**改造它**,不重写
- ❌ 没有 → 继续查③

### ③ 查血泪教训 (避免重蹈覆辙)

```bash
grep -nE "<keyword>" ~/.claude/projects/-Users-hgxszhj-x-videos-dowloads/memory/MEMORY.md
grep -nE "<keyword>" ~/memory/projects/x_videos-dowloads.md 2>/dev/null
grep -nE "<keyword>" ~/memory/daily/$(date +%Y-%m-%d).md 2>/dev/null
```

**判定**:
- ✅ 有相关 memory → **必读全部条目**,在 commit message 里说明如何避坑
- ❌ 没有 → 才允许开始写

## 反例 (踩过的坑)

| 写过的 | 实际已有 | 浪费 |
|--------|---------|------|

> 这些案例的真实记录在 `~/.claude/projects/.../memory/MEMORY.md` 的相关条目里。

---

## AI 决策树

```
用户: "写一个 <X>"
  ↓
AI: "30 秒,先查 3 项"
  ↓
跑完 grep
  ↓
[查到现成] → 告诉用户"已有 X 在 <path>,要不要复用 / 改造?"
  ↓
[没查到] → 继续往下做
  ↓
开始写代码前,在 commit message / PR 描述里写:
  "已查 skill/module/memory,均无现成实现,理由: <why new is justified>"
```

---

## 例外条款

以下情况**可以跳过 ②③ 但必须 ①**:

- 紧急 hotfix (production down) → 事后补查
- 用户明确说"我知道有 X,就要新的" → 记入 memory 说明为什么覆盖

**永远不能跳过 ①**(查 skill 是防止你在另一个项目里又写一遍一模一样的工具)。

---

## 维护规则

- **反例表持续追加**: 每发现一次"重复造轮子",就在反例表加一行 + 写一条 memory
- **过期清理**: 反例超过 1 年的条目,如果原模块已删/已重构 → 移到 `archive/`

---

## Why / How to apply

**Why**: AI 的默认倾向是"接到任务 → 立刻动手"。没显式 checklist,这个倾向就压倒了"先复用"。**`Simple > Complex`**(13 规则 #2)的真正落地不是"代码少",而是"组件少"。

**How to apply**: 把这份 checklist 复制粘贴到任何"帮我写 X"的 prompt 开头;或在 SKILL.md 加 hook 自动注入。
