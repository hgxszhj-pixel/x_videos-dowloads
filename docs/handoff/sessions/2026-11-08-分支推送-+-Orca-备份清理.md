## 推送前：先确认要不要 fork

## 坑 1：curl 28 低速中断（与 release 资产 504 同源）

首次推送失败：

```
错误：RPC 失败。curl 28 Operation too slow. Less than 1000 bytes/sec transferred the last 30 seconds
send-pack: unexpected disconnect while reading sideband packet
致命错误：远端意外挂断了
```

**先排除体积嫌疑再归因给网络**：复算待推送 pack = **743 KB**（`git pack-objects --stdout --revs`）——
743 KB 传不动，不是包太大，是**链路低速被 git 主动掐断**。
与 2026-11-08 记录的 release 资产 504 同一根因（本机到 GitHub 的连接质量）。

修法（关掉低速中止 + 放宽缓冲）：

```bash
git -c http.lowSpeedLimit=0 \
    -c http.lowSpeedTime=999999 \
    -c http.postBuffer=524288000 \
    push origin gitbutler/workspace
```

一次过。

## 坑 2：`git push ... | tail -20` 把失败伪装成成功

第一次用 `git push origin gitbutler/workspace 2>&1 | tail -20` 跑，输出末尾是：

```
致命错误：远端意外挂断了
Everything up-to-date          ← ← ← 这行是假的
[exited with code 0]            ← ← ← 这也是假的
```

`Everything up-to-date` 和 **exit 0** 都来自管道下游 —— 退出码取的是 `tail` 的，不是 `git` 的。
差点据此认定推送成功。

**判据**：验证远端状态**必须读实际 ref**：

```bash
git ls-remote origin refs/heads/gitbutler/workspace
# 必须与 git rev-parse <branch> 相等
```

写验证脚本时同理：**管道会吃退出码**，要么 `set -o pipefail`，要么别用管道包 git。

## 坑 3：全局 pre-push hook 的「Can't find lefthook」在本仓不存在

推 Tendedero 时报过全局 `~/.git/hooks/pre-push` 找不到 lefthook。本仓**没有这个问题**：

```
git config --get core.hooksPath
→ /Users/hgxszhj/x_videos-dowloads/.git/hooks
```

`core.hooksPath` 指向仓内 `.git/hooks` ⇒ **全局脚本不生效**，且仓内本来就没有 pre-push。
⇒ 那句报错在本仓不会出现，别去绕。
