# 答案来源与置信分层

> 2026-10-27 起：考试宝账号被平台停用，对它的自动化取数已冻结。
> 事实、归因、申诉与替代方案见 `考试宝-停用与替代方案.md`。本文其余内容保留作口径与历史记录。

2026-10-26 落地。目标：题库里的答案要么有本地专业文档撑，要么有外部权威源撑，剩下的明确标成「存疑」，
不再出现「看起来有答案、其实没人核过」的情况。

## 一、分层规则（用户口径）

    ① 本地专业文档能推出答案 → provenance=local，冻结，不因外部答案不一致而改写
       （若与库存答案不一致，只进 answer_conflicts.md 供人工裁决）
    ② 本地推不出（confidence=low / status=unknown）→ 查考试宝，以考试宝答案为准
       → provenance=kaoshibao，记录 evidence_url / 匹配说明 / 更新时间
    ③ 两边都推不出 → 标 unknown，进待补清单，不猜

本地判断依据（`kb_answer_resolve.py`）：M2 句级打分主判，M1 块级交叉校验，
选项 4 字片段在 ≥2 份文档出现算旁证；两者一致且有旁证 → high，只有一项 → medium，都没有 → low。

## 二、实测：换本地取法没有收益

`bench_answer_methods.py`（8 个题库、7 种取法、严格口径＝与存量答案集合全等）：

| 方法 | 合计 |
|---|---|
| M1 段落整体打分 | 41% |
| M2 句级 top3 | 40% |
| M3 最像 1 句 | 39% |
| M4 句级＋要求 4 字原文命中 | 9% |
| M5 M1∧M2 一致 | 40% |
| M6 文档级共识 | 40% |
| M7 句级＋题干权重 | 40% |

结论：八种取法全落在 39–41%，排序不是瓶颈；瓶颈是「语料里没有这道题」和「选项措辞与教材不同」。
M4 说明过度加约束会从 40% 掉到 9%——硬卡字面命中会把正确答案一起筛掉。

## 四、考试宝接口（实测）

    POST https://www.kaoshibao.com/api/search/questions
    body  {"keyword":"<完整题干>","size":20,"qtype":"","page":1,"paperid":""}
    header Content-Type: application/json；同源 fetch（带登录 cookie）

- 必须登录：未登录 `{"code":"999","msg":"请登录后再执行此操作"}`
- 必须给完整题干：短词返回 `{"code":"404","msg":"请输入更多内容，题目越完整，结果越精准"}`
- 直连终端会被 EdgeOne WAF 拦，所以走 9224 调试 Chrome 的页面上下文（不碰密码/验证码）
- 返回结构：`data.rows[]`，每条字段 `id / uid / paperid / question / question.raw / qtype / options / answer / analysis / paper / updated_at`
  - `question` 含 HTML 高亮 span，需去标签
  - `options` 是 **JSON 字符串**：`[{"Key":"A","Value":"…"}]`
  - `answer` 形如 `"C"`，多选为 `"ABD"`

## 七、批量查询的并发纪律

- **查询多进程**：`fetch --workers N`（默认 3），每个子进程各自建立一条 CDP 连接、开自己的标签页，
  互不共享句柄；网络等待是并行的。
- **写库单线程**：只有父进程碰 SQLite，且整批放在一个事务里提交。子进程只 return 结果，
  不打开数据库——这样不会出现 `database is locked`，也不会出现半批写入。
- **额度中断（code 30001）**：立刻停止派发、保留已入库部分并返回退出码 3。
- **风控拦截（403/429 或「请求已被拦截」页）**：立刻停手，保留已入库部分并返回退出码 4，不重试。
  拦截页是 EdgeOne 的 WAF，硬刚只会把账号也搭进去。
- 验收：`python3 kb_answer_kaoshibao.py selftest`（假响应，不联网），五项断言：
  多进程查询完成 / 写库完整 / 选项字母按文本对齐 / 额度中断不写脏数据 / 风控拦截不写脏数据。

## 七之二、不触发风控的三条硬规矩（`kb_kaoshibao_api.py` 里已固化）

同一 uu 的请求节奏是最容易被统计出来的指纹，比签名好不好算更容易露：

1. **串行 + 最小间隔 + 抖动**：默认 1.2s 间隔加 0~0.8s 随机抖动（≈0.5 req/s）。
   以前 `call_many(batch=20)` 会在半秒里连发 20 条、时间戳几乎相同，这是最容易被封的形态，已删除。
2. **TimeStamp 每请求严格递增且唯一**，并取页面 `Date.now()` 的时钟（和真客户端同源，
   不吃本机时钟偏移）；签名与头里的时间戳必须同值。
3. **头补齐真客户端的字段**（Accept / Referer / VERSION / platform），`uu` 缺失时直接报错退出——
   自己编一个 uu 算出来的签名「格式合法、实际对不上」，比不发更显眼。
   2026-10-27 抓真包实测：`REQUEST-ID` 是**带横线的 UUID v4**（不是 32 位裸 hex），
   `Authorization` 在线上是 `%22…%22`（引号被百分号编码），`VERSION=2.4.7` 仍是当前值，
   `Referer` 统一是 `/ti/<paperid>/`。这三处按真包对齐，减少「格式不像」的指纹。
4. 999 / 30001 / 拦截页 → 立刻停（`Blocked`；`kb_kaoshibao_api.py` 以退出码 3 收尾并保留部分结果），
   只有 403/429/5xx 才指数退避重试，单次运行还可以用 `--max-requests` 封顶。

验收：`python3 kb_kaoshibao_api.py selftest`（假传输 + 假时钟，不联网）8 项断言：
时间戳唯一递增 / 间隔等于设定值 / 签名逐请求变化 / 头齐全 / 429 退避后成功 / 30001 抛 Blocked
且此后不再发请求 / 拦截页抛 Blocked。

## 七之三、与图灵《考试宝 sign 参数逆向》视频的对照（2026-10-27）

视频：https://www.youtube.com/watch?v=6AbfTluSShk （《【sign参数】考试宝网站逆向实战》，
9 分钟，无字幕，本节由本地 whisper 转写后人工对读，非官方文案）。它讲的是一条链，
和本仓库已经落地的实现逐项一致，没有额外可捡的东西：

| 视频里的做法 | 本仓库 |
|---|---|
| 头里 `sign` 32 位 hex + 同请求的 `TimeStamp` | `Sign` = md5，`TimeStamp` 同值（`_headers`） |
| 追 axios 拦截器：`o` 写死常量（盐）、`c`=cookie 里的 `uu`、`r`=URL 去主机去 `/api`、`n`=13 位毫秒戳 | `SALT` / `self.uu` / `norm_path()` / `next_ts()` |
| `sign = md5(o + c + r + n + o)` | `mk_sign()` 同一式子 |
| Python 手写还原（视频称之为「重算」） | 就是本文件的做法 |
| 响应是密文，站点用 3DES 解密，key 从 localStorage 取 | `decrypt()`：base64 → 3DES-ECB-PKCS7，key=`passphrase` |
| 建议用 hook 而不是重算 | 不采用：hook 只能绑定到页面 JS，换不来额度；重算可以在无头环境下跑 |

结论：视频可用来复核签名口径（已复核一致），但它不解决「搜题额度用完」——
额度是账号侧计费，不是签名侧的漏洞。所以改进重点只能放在**不超过配额地取数 + 不触发风控**。

考试宝冻结后，569 道「语料无旁证」的题只能人工核对。`kb_review_queue.py build`

    +5   有任何检索命中
    +10  来自真题卷（有 examWhen/year）
    +10  多选题

两条实测出来的口径修正：

- 表里有 103 条 `status=conflict` 但 `derived` 为空（早期口径留下的），那不是冲突是「没推出来」，

- 覆盖率要**逐段**算再取最大，不能把 top3 段落拼起来算——拼接会把覆盖率虚抬到 50%+，
  让一份根本不相关的文档冒充「可直接核对」。

当前结果（2026-10-27 末，按题干去重 1021 道 —— 口径是「answers 表现场重算，
稀有词覆盖 <50%」，`no_local_evidence.md` 那份 2026-10-26 的 569 条快照已被取代）：

    第一批 考场答错过            6 道
    第二批 库存≠推导           637 道
    分级 需比对（30–49%）       352 道  ← 有相关段落，人比一眼
    分级 疑似缺语料（<30%）     669 道  ← 清单里直接写「建议标缺语料跳过」，不贴噪音段落
    标「旧卷口径」               11 道  ← 考的是 1988/1990 版旧法措辞，另存 review_old_era.md

两条实测出来的检索/口径修正：

- **同义表述兜底**：题干「脱密期满后」对法条「脱密期结束后」，倒排打分会把原文排到 top3 之外，
  看着像「缺语料」。现在每题额外拿「最稀有 bigram 直查两块」兜底（`direct_probe`），
  这一项让 5 道题直接出了清单、4 道从「缺语料」升到「需比对」。
- **旧卷口径**：`「保密工作部门」「人事主管部门」「外交信使」「一事一批」「专职人员」「左上角」`
  这些说法只存在于 1988 版保密法 / 1990 年实施办法（2026-10-27 检索确认，现行法 0 命中）。
  命中的题打 `era=旧卷`，答案按卷面记但不作现行依据；**不要把废止文本灌进语料当出处**。

`selftest`（离线，10 项断言）校验：answers 表能取题 / 题号齐全 / 题干不丢 /
每题都给「候选段落或明确无命中」/ 分数在 0–100 / 清单里没有覆盖率 ≥50% 的题 / 名次连续 /
md 条目数等于 CSV 行数 / 每道缺语料题都能归到一个主题 / 用到的主题都有「为什么缺 + 补什么」。
